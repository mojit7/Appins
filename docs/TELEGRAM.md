# ربات تلگرام دستیار مالک (مرحله ۷)

ربات فقط برای مالک فروشگاه فعال است. **وضعیت زنده: NOT LIVE-VERIFIED** — تا زمانی که توکن واقعی پیکربندی و آزمون سرتاسری موفق نشود، ربات «فعال» تلقی نمی‌شود.

## معماری

- **Webhook رسمی تلگرام** (setWebhook): تلگرام آپدیت‌ها را به `POST /telegram/webhook` می‌فرستد؛ احراز درخواست با سرصفحه رسمی `X-Telegram-Bot-Api-Secret-Token` (مقدار `TELEGRAM_WEBHOOK_SECRET`) و مقایسه زمان‌ثابت انجام می‌شود.
- غیاب هر یک از سه متغیر (توکن، شناسه مالک، سرّ webhook) ⇒ ماژول غیرفعال و همه مسیرها `503 TELEGRAM_MODULE_NOT_CONFIGURED`.
- مسیر `/telegram/webhook` عمومی است (تلگرام نشست ندارد)؛ مسیرهای راه‌اندازی (`setup/teardown/info`) پشت گارد نشست سرور هستند.
- توکن فقط در متغیر محیطی سمت سرور نگه داشته می‌شود و از لاگ‌ها حذف می‌شود (redact سرصفحه‌های حساس + عدم قرارگیری توکن در پیام خطاها).

## فرمان‌ها (فقط هویت مالک)

- `/start` خوش‌آمد فارسی، `/help` راهنما
- `/status` وضعیت فروشگاه: محصولات، پیش‌نویس‌ها، کارهای انتشار (از داده ماندگار)
- `/upcoming` پنج زمان‌بندی بعدی از صف pending
- `/drafts` پنج پیش‌نویس اخیر؛ دکمه تأیید فقط برای وضعیت «در حال نگارش»
- تأیید پیش‌نویس از callback: `approve:<uuid>` — فقط از چت مالک، فقط برای وضعیت draft، گذار به ready

## امنیت و پایداری

- **اعطای دسترسی:** هر پیام/callback فقط با تطبیق شناسه چت با `TELEGRAM_OWNER_ID` پردازش می‌شود؛ سایرین پیام رد می‌گیرند و داده‌ای نمی‌بینند.
- **جلوگیری از اقدام تکراری:** (۱) dedupe شناسه آپدیت (حافظه محدود ۵۰۰ مورد) برای بازپخش تلگرام؛ (۲) idempotency وضعیت: تأیید فقط از وضعیت draft ممکن است و تکرار آن پاسخ «قبلاً پردازش شده» می‌دهد بدون تغییر وضعیت.
- **اعتبارسنجی callback:** قالب `approve:<uuid>` با عبارت باقاعده؛ داده نامعتبر/شناسه ناموجود بدون هیچ تغییری پاسخ می‌گیرد. همیشه answerCallbackQuery صدا می‌شود (الزام رسمی).
- **محدودیت نرخ و شکست موقت:** در پاسخ 429 مطابق `retry_after` حداکثر یک‌بار تلاش مجدد (با سقف انتظار) و سپس رها می‌شود؛ خطای دائم بدون تلاش مجدد رها می‌شود. webhook همیشه ۲۰۰ برمی‌گرداند تا تلگرام ارسال تکراری بی‌پایان نکند؛ خطاها ثبت و رها می‌شوند.
- **اعلان نتیجه کار انتشار:** کارگر زمان‌بند پس از هر نتیجه ماندگار (succeeded/failed_permanent) اعلان می‌فرستد؛ نتیجه گذرا اعلان ندارد (تلاش مجدد خودکار در جریان است). شکست ارسال اعلان سرنوشت کار را عوض نمی‌کند.

## پیکربندی و راه‌اندازی (go-live)

1. ساخت ربات با BotFather و گرفتن توکن.
2. گرفتن شناسه چت مالک (از پیام /start مالک، مثلاً با getUpdates پیش از تنظیم webhook).
3. تنظیم متغیرها: `TELEGRAM_BOT_TOKEN`، `TELEGRAM_OWNER_ID`، `TELEGRAM_WEBHOOK_SECRET` (۱ تا ۲۵۶ نویسه از A-Z a-z 0-9 _ -).
4. فراخوانی `POST /telegram/webhook/setup` با نشانی عمومی HTTPS (مثلاً `https://<host>/telegram/webhook`) — سرّ به setWebhook پاس می‌شود.
5. راستی‌آزمایی با `GET /telegram/webhook/info` و آزمون سرتاسری فرمان‌ها.
6. برای توقف: `POST /telegram/webhook/teardown`.

## مراجع رسمی (مشاوره‌شده ۲۰۲۶-۱۰-۱۱)

- Telegram Bot API — https://core.telegram.org/bots/api (setWebhook و پارامتر secret_token، سرصفحه X-Telegram-Bot-Api-Secret-Token با محدودیت نویسه‌های مجاز؛ getWebhookInfo/deleteWebhook؛ sendMessage؛ answerCallbackQuery؛ پاسخ 429 با parameters.retry_after؛ زبان پایدار فعلی Bot API).
- Telegram Bot API — Webhooks guide: https://core.telegram.org/bots/webhooks (الزام HTTPS عمومی؛ در شکست تحویل، تلگرام «پس از تعداد معقول تلاش رها می‌کند»).
