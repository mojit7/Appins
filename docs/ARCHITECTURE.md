# یادداشت‌های معماری

## تصمیم‌ها
1. **Runtime**: Node.js 20 + TypeScript strict. پایانگاه API با Fastify (خطاهای متمرکز، تزریق وابستگی، تست‌پذیری با `app.inject`).
2. **جدا‌سازی لایه‌ها**: `server` (HTTP) — `domain` (منطق کسب‌وکار و اسکیماها) — `infra/persistence` (مرحله ۲) — `integrations` (اینستاگرام/تلگرام/AI) — `jobs` (کارهای پس‌زمینه). UI وب در `web` (Vite + React، فارسی RTL).
3. **اعتبارسنجی**: zod به‌عنوان مرجع تک‌حقیقتِ شکل داده‌ها (env، دامنه، درخواست‌ها).
4. **خطاها**: سلسله‌مراتب `AppError` + `setErrorHandler` متمرکز؛ پاسخ خطا فارسی و بدون نشت جزئیات داخلی.
5. **پیکربندی**: فقط از طریق متغیرهای محیطی با اعتبارسنجی هنگام راه‌اندازی (فرآیند در حالت نامعتبر بالا نمی‌آید).
6. **امنیت**: همه توکن‌ها سمت سرور؛ مرورگر هرگز به متا/تلگرام مستقیم دسترسی ندارد؛ نشست با `SESSION_SECRET` ≥ 32 کاراکتر.

## ادغام‌های بیرونی (فقط بر پایه مستندات رسمی)
- **اینستاگرام/متا**: جریان رسمی برای حساب‌های Professional (Business/Creator). نکته/بلاکر ثبت‌شده: طبق مستندات رسمی متا، انتشار محتوا (Content Publishing API) و دسترسی به Insights به حساب IG حرفه‌ای نیاز دارد و روند اتصال توکن از طریق جریان‌های رسمی متا انجام می‌شود؛ پشتیبانی «Instagram Login» مستقیم برای همه سرصفحه‌ها در دسترس نیست. لایه `integrations/instagram` به‌صورت Interface عایق‌بندی شده تا پروایدر احراز هویت بدون تغییر لایه دامنه قابل تعویض باشد. تا مرحله ۴ هیچ ادعای اتصال نداریم.
- **تلگرام**: Bot API رسمی (long polling در مرحله ۷؛ کلیدهای توکن فقط سمت سرور).
- **هوش مصنوعی**: صرفاً تولید متن کپشن فارسی؛ کلید سمت سرور.

## نکات
- رقبا پایش نمی‌شوند (خواسته صریح محصول).
- زمان‌بندی انتشار فقط در حدی که API رسمی متا اجازه دهد؛ در غیر این صورت «پیش‌نویس» و یادآور.
